# 个人活动数字孪生教学原型

双击 `打开演示.cmd` 或用浏览器打开 `index.html`。页面包含构建时生成的数据快照，可离线打开。此目录内有个人健康记录副本，演示文件同样包含该账号的时间序列和回顾预测。

| 页面 | 操作 |
|---|---|
| 个人状态 | 切换指标与事件。可查看日中位数、单次运动、睡眠阶段及预警类别计数。 |
| 游泳心率回放 | 选择留出场次及预测时距，播放或拖动时间轴。蓝色点在预测发出后出现，目标观测在该窗口结束时显示。 |
| 游泳计划热量 | 调整整场计划时长，查看设备热量条件估算和三档示例。散点为真实场次。 |
| 静息心率验证 | 查看逐日预测、基线和误差。切换睡眠配对终点，比较后续静息心率或午后压力。 |

## 复跑

从本目录运行以下命令。当前构建使用 Python 3.10.4。依赖已安装时可直接运行第二条。

```powershell
py -3.10 -m pip install -r requirements.txt
py -3.10 -X utf8 build.py
```

`data/健康数据.xlsx` 是全量 Excel 的本地副本。`build.py` 从该副本重新解析并生成一次独立运行。`swim.py` 复用 11 月 6 日的工作簿读取、运动窗口和模型拟合代码。`vendor/garmin_lab/registry/` 保留本地克隆的 EpiCoach 台账源码与 MIT 许可。`demo.html` 是页面模板，最新完成的构建发布到 `index.html`。

每次构建在 `runs/` 新建一个目录，保存 `metrics.json`、逐样本 CSV、睡眠配对 CSV、SQLite 台账和可离线打开的页面快照。模型输入截止和日期切分可在 CSV 中查阅，模型版本由运行编号、模型名称、训练截止及输入和源码哈希关联。

## 本版验证口径

- 游泳心率以前八场开发、后三个日期共六场回放。沿用 30 秒最近值和 120 秒岭回归，候选目标窗缺测时可登记预测，评分留空。日期等权 MAE 先在每场内求平均，再依次按场次和日期等权汇总。
- 运动热量从前四个游泳日开始训练，余下日期依次预测。用实际整场时长作为回顾评估的给定条件，比较不含时长的历史中位数、单位时间热量和非负斜率线性回归。约束线性模型须在较早的至少三个已评分日期相对简单时长模型达标后才用于下一折。界面曲线使用完整 14 场校准，历史逐场误差来自滚动回测。
- 次日静息心率用最早 14 个有效配对启动滚动训练，随后按日评分。比较历史七个有效日中位数、最近值和两个单活动变量的岭回归候选。静息心率和日活动的可用时刻均设为记录日期结束时，作为离线回放约定。
- 本次实施采用项目演示门槛。候选相对指定基线的日期等权 MAE 至少改善 5%，且须在超过半数评估日降低误差。热量启用按当折训练时长范围内的结果判断。静息心率的运动分钟候选须同时优于两条基线。
- 热量估算输出对应设备整场记录，默认情景为 25、40、55 分钟。前日活动与静息心率、睡眠与后续观测均使用同一账号的历史回顾数据。未执行的情景在页面上是估算，台账中的热量评分只对应历史场次及其实际时长条件。
