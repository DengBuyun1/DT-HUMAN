# 第二版实施与复跑

在项目目录运行 `py -3.10 -X utf8 v2/run.py`。默认读取 `data/健康数据.xlsx`，也可用 `--workbook` 指定本地授权副本。每次运行输出到独立的 `runs/v2-*`，打开其中的 `index.html` 即可查看。使用 `py -3.10 -X utf8 v2/verify.py <运行目录>` 核对文件哈希、台账和预测时间。

运行 Chronos-2 对照时，使用包含 PyTorch、Transformers 和 Chronos 运行依赖的 Python 环境，执行 `py -3.10 -X utf8 v2/run.py --chronos --models-dir <模型目录> --device cuda`。模型目录包含本地 `chronos-forecasting` 和 `chronos-2-weights`。CPU 环境可改为 `--device cpu`。本次实跑使用 PyTorch 2.4.1+cu118 与 Transformers 4.57.6。权重保持冻结，LoRA 由开发门槛决定是否进入另一次训练。

## 实验口径

- 心率前六个游泳日期启动，后五个日期按日滚动评估。同一天复用训练参数，每次游泳重置局部趋势状态。30秒与120秒均预测目标30秒窗的设备心率中位数。
- 原版 Ridge、训练加权 Ridge、最近值和两状态 Kalman 在相同的输入窗口对照。Kalman 用 NumPy 实现标准局部趋势前向滤波。噪声比和 Ridge 正则只用以前日期选择。
- 回放先评分到期预测，再接收观测并更新状态，最后登记未来预测。台账登记预设参考模型，全部对照输出写入逐窗 CSV。参考模型和回测结束后建议的模型分别保存。
- 发出率以记录范围内可定义的目标窗为分母。记录结束前已发出、但结束后才到期的预测记为撤回。输入缺失与目标缺失分别记录。误差参考使用此前至少三个已评分日期的带符号误差分位数。
- 热量按前四个日期启动。用训练场次的每分钟热量中位数作为强基线，对照约束直线及旧滚动策略。分别比较总时长和运动结束才可获得的活动时间。展示曲线用全14场校准，回测误差来自过去日期的参数。
- Chronos-2 对比3、10、20个完整历史窗口，固定预测120秒。各档与同批 Ridge 比较，另保存三个档位共同样本的结果。上下文选择只读先前日期。长上下文丢失的窗口纳入覆盖率统计。
- 静息心率沿用现有对齐和回测。睡眠、压力、血氧、体重与体成分继续呈现实测。

本轮沿用先前已查看的单人历史数据。实验比较和误差参考均适用于这次回顾评估。
